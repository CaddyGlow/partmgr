# JFFS2 bounded multi-node regular-file editing

`Jffs2Editor::write_range` replaces one contiguous range from a deferred common `FileRead`, with an explicit final length and modification/change seconds. `truncate` publishes a new length, including explicit zero-filled extension. Both retain the same reachable native inode, all existing hardlink names, supported mode/UID/GID/flags and access seconds. Names and directory-entry timestamps are unchanged. Symlinks/directories and opaque metadata remain outside these methods. The original single-name fresh-inode `replace` API remains available with its original narrower contract.

The editor streams the input into bounded NONE nodes: `file_bytes` is a per-node limit, never above 32768, additionally limited by the erase boundary. The input may exceed that buffer and span many nodes/erase blocks. Total retained intent bytes and node count remain bounded by `journal_bytes` and `slots`; no whole file or image is buffered. Every allocation, source identity clone and parser/working map is charged to Resources. Source identity/length are checked before and after each bounded read sequence; causal errors, cancellation, overflows, node/space limits and insufficient shared budget fail before target mutation. The exact input bytes are materialized into the retained external intent during preflight; later commit/recovery needs no source handle. This does not detect arbitrary source byte changes under an unchanged identity/length; callers must honor common source stability contracts.

Operation code 7 appends sequential higher-version data nodes and a mandatory final zero-data metadata node. Extension gaps receive canonical ZERO nodes (zero compressed bytes, nonzero logical size), including regions previously removed by truncation. The final metadata record publishes final length/timestamps after all preceding nodes have been read back and flushed. Native readers may still observe partially updated content before final publication: these are offline exact-bound-intent transactions, not mount-visible atomic file edits. Torn nodes require recovery before strict reopening. The same legal NOR replay rule, full baseline/final digests, alternating external headers, sticky uncertainty and retained cancellation authority apply as in the [append/recovery protocol](filesystem-jffs2-edit.md).

Semantic preflight and recovery require one reachable regular inode, exact increasing versions, supported unchanged metadata, contiguous data offsets, exact final length, exact ZERO extension-gap coverage and a final metadata node. All names, deletion histories and unrelated inode headers remain unchanged. Every new data interval must resolve to its exact recorded physical payload; unchanged intervals must retain the baseline physical mapping and extension gaps must resolve to holes. This indexed comparison is bounded by fragment/work limits and checks cancellation; it does not rehash a potentially huge untouched logical file. Full source-region digests still bind all bytes outside appended slots. Checksum-recomputed malformed intents reject before either target or journal writes.

Primary references are Linux [file writing and explicit ZERO holes](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/file.c), [latest-isize reconstruction](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/readinode.c), and the native header/CRC ledger. The consulted `file.c` is archived under `/data/cache/partmgr-jffs2-spec`. The reader preserves native version overlay semantics: it does not invent historical-isize truncation for retained accurate records. A later extension is authored with explicit ZERO nodes so discarded tails cannot reappear. Ordinary mounted-kernel mutation also changes obsolescence state; our offline append protocol retains historical records and relies on higher-version ZERO/data coverage.

Portable tests cover both endian encodings, non-UTF-8 names, hardlink identity, a 5000-byte source split into 256-byte nodes, exact metadata, shrink then ZERO extension, independent raw ZERO histories, late causal source failures, identity/length changes, cancellation and cap refusal. Range operations are cut at every target/journal program/flush boundary under four independent retained/discarded volatile target/journal combinations; recovery itself is cut and restarted across the same combinations. Repeated COMPLETE recovery writes neither object. Rehashed negatives cover noncontiguous offsets, duplicate versions, inconsistent sizes/timestamps and malformed final publication.

The explicitly enabled native gate requires mtd-utils and Jefferson. It independently generates an initial/incremental history, then applies range editing to the same native inode reached through hardlink names. `jffs2dump` checks completed node CRCs, and the unchanged Jefferson core independently reconstructs a 5013-byte file with preserved 13-byte prefix plus a 5000-byte patch across 256-byte nodes. Jefferson overlays node data but does not implement isize truncation: this gate supplies no independent native shrink/zero-tail oracle. Those semantics have portable raw-fixture and primary-source evidence. Native mount/recovery, physical NOR power loss, NAND/OOB/ECC, compression authoring and generalized GC packing remain unproven or later work.

Jefferson's CLI guesses endianness from the first two bytes, which are erased FF after the audited GC history. The gate therefore invokes its unchanged `set_endianness`, `scan_fs` and `dump_fs` core through the recorded Python interpreter with explicitly declared LE geometry. It passes the exact full raw image, performs no node rewriting or prefix removal, and retains the core source/interpreter/tool hashes and command arguments. This addresses extractor framing, rather than weakening payload comparison or modifying the tool.

The native v3 receipt is `/data/cache/partmgr-jffs2-range-native-final4/jffs2-owned-nor-append-gc-v1.txt` (legacy filename, profile `jffs2-owned-logical-nor-multi-node-range-v3`). Its final enabled invocation and fixed test-executable path are recorded after the source/tool/executable end checks. The earlier v1/v2 receipts remain historical checkpoints. All 24 editor tests and the full locked all-feature host suite pass; all-target/all-feature locked Clippy with warnings denied and `cargo fmt -- --check` pass. Host temporary files use `TMPDIR=/data/cache/partmgr-jffs2-tmp` because `/tmp` exhausted its space. The 1GiB extension regression retains less than 2MiB under the declared test caps, uses a journal below 2KiB and reads a distant zero range without buffering the logical file.

An adversarial source getter that switches to a different-length identity key is rejected as stale without panic or target writes; the initial identity is captured once before its bounded fallible copy.
