# Opt-in offline JFFS2 compressed authoring

`Jffs2BuildPlan::from_tree_compressed` adds `Jffs2BuildCompression::Rtime` or `Zlib` to the existing common-tree builder. Existing options/limits struct literals, `from_tree`, report fields and strict editing remain compatible. This is new unpublished image authoring through `Storage`; it is not an existing-image compressed editor or hardware flash writer.

Layout preflight still reserves every regular-file data node's worst-case aligned NONE span, including erase-boundary fit, metadata, dirents, cleanmarkers and complete image capacity. It never relies on compression gain to fit an image. Consequently a source whose NONE representation exceeds the destination rejects before mutation even if a compressed representation might fit. Actual compressed nodes retain those deterministic reserved locations; unused span/tail bytes become `0xff`. Dynamic packing based on compressed sizes is outside this profile.

Regular files use bounded increasing-offset nodes, with exact native `isize` and `dsize`. The selected codec is used only when its complete encoded output is smaller than input. RTIME follows Linux's [literal/run format](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/compr_rtime.c). ZLIB uses the published `flate2` 1.1.10 `rust_backend`, low-level `Compress` API, fixed level 3 and RFC1950 framing with Adler checksum, matching native [ZLIB framing](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/compr_zlib.c). The exact locked backend/source version defines bitstream determinism. Incompressible nodes fall back to NONE without expansion. Native data CRC covers the encoded bytes; header/node checksums include actual lengths and codec. Output never grows beyond the input-sized encoded buffer.

When existing `zero_nodes` is true, wholly zero logical chunks become compact ZERO nodes before any codec is invoked. This recognizes the source stream's sparse/zero semantics but transforms allocation shape explicitly, as the existing report records. ZERO handling remains optional; with it disabled, zero content may be compressed ordinary data. Symlinks stay complete uncompressed exact-byte nodes and are never followed. Hardlinks share one native inode and data stream; byte names, explicit UTF-16 conversion policy, metadata defaults and preservation rejection retain their existing contracts.

Every deferred short read is surrounded by tree identity revalidation and stream identity/length checks. Original and operation cancellation contexts remain active. No source file or image is buffered in full by the engine. Before the first write, emission reserves existing streaming/node buffers plus an input-sized encoded output buffer and conservative codec state (2048 bytes RTIME, 2097152 bytes ZLIB). Node input is capped at 32768 bytes. Per-node codec execution is bounded by that input cap; inventory/layout retains its explicit work limit, and deferred short-read loops consume at least one logical byte per successful call. Libraries receive exact bounded output space rather than a growing convenience encoder.

Emission fully initializes the image, performs one explicit flush, regenerates every byte through the same deferred source and compares full readback/SHA-256. Source changes, I/O failures, cancellation, partial target writes, failed flush and readback mismatch retain the existing causal error and mutation/flush uncertainty report. A budget failure before emission buffers are allocated makes zero target writes. This proves modeled behavior and actual regular-file flush calls, not power-loss durability.

Portable tests cover both codecs and endian orders, reversed source enumeration, 37-byte short reads, hardlink identity, non-UTF-8 names, explicit metadata values, exact unfollowed symlink target, ZERO extents, incompressible NONE fallback, worst-case insufficient-space rejection, memory exhaustion, causal source errors and target partial/flush/readback failures. Default builder/editor contracts remain independently tested.

The enabled native gate uses `JFFS2_BUILD_COMPRESSION=rtime` or `zlib` with the existing explicit evidence/tool variables. It independently produces an uncompressed mkfs image, inventories `RawDisk -> Jffs2Volume -> Jffs2TreeSource`, and authors directly from that deferred source without extracting a host tree. Eight cases per codec combine LE/BE, ZERO on/off and source order. Completed images must contain at least 20 actual compressed data nodes; jffs2dump validates CRCs and shared native hardlink inode numbers, Jefferson compares the complete 90013-byte payload and exact symlink target, and the compressed engine reopens with a complete clean audit. Same-input reversed-order image hashes must match. Exact arguments, tools/interpreter/parser/binary hashes, compiled/live source equality and end revalidation are retained. Other codecs, compressed existing-image mutation and physical NOR/NAND/OOB/ECC remain unfinished scope.
