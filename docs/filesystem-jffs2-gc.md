# Offline JFFS2 multi-node garbage collection

`Jffs2Editor::collect` relocates reachable regular files as bounded NONE data nodes and compact ZERO nodes followed by a final metadata node. The caller's `file_bytes` cap bounds each data node, rather than the logical file length. Original native inode numbers, every hardlink, exact logical bytes, mode, UID/GID, timestamps and supported flags remain equal. Raw node locations and version numbers change. Both declared byte orders are supported. This extends the [external-intent protocol](filesystem-jffs2-edit.md); it does not change the immutable reader's ownership contract.

Every accurate inode header in the victim contributes a conservative relocation dependency, including historical headers. Latest live dirents and deletion tombstones in the victim are also relocated. Recovery checks that every required reachable inode has a replacement group. Each regular-file group must have successive versions above the previous maximum, identical native metadata and `isize`, exact contiguous logical coverage, valid NONE/ZERO sizes, and a final empty metadata record. Recomputed journal hashes cannot authorize malformed coverage, changed metadata or changed content. Indexed comparisons use bounded scratch buffers; identical retained data mappings and matching zero extents need no payload materialization. Thus a 1 GiB ZERO extent remains compact.

Before erase, recovery validates the complete resulting namespace, content and absence of live references into the victim. Replacement bytes are read back and flushed before durable COPIED publication in the separate journal. Only COPIED permits victim masking with its bound saved preimage and completion of a partial erase. PREPARED requires the victim to remain unchanged. NOR replay requires `(observed & expected) == expected`. The journal never restores erased bits. COMPLETE recovery validates actual final bytes and makes no writes.

Allocation uses pristine erase blocks and reserves the leading 12 bytes of each destination block. Dense packing into partially occupied blocks is outside this profile. Compression, fragmented symlink histories, mounted kernel mutation, hardware durability, NAND/OOB/ECC and physical power-loss behavior remain unsupported. The source and destination retain explicit logical NOR geometry; no geometry is guessed.

Portable evidence includes independently encoded fragmented histories with 5000 data bytes, a ZERO tail, native hardlinks and both byte orders, relocated with a 256-byte data-node cap. Every modeled target/journal write and flush cut, including interruptions during recovery, is restarted under all four combinations of retaining or discarding volatile target and journal bytes. Rehashed semantic-negative intents reject without either target or journal writes. Memory exhaustion and cancellation reject before mutation; leases refund after completion. A separate 1 GiB logical-zero regression uses less than 8 KiB of journal and less than 2 MiB of retained resources.

The enabled native gate requires mtd-utils and Jefferson; missing tools fail. It retains exact commands, versions, raw artifacts, source/tool/interpreter/binary hashes and start/end equality checks. `jffs2dump` validates completed node CRCs; unchanged Jefferson's explicit-LE core compares the complete 5013-byte relocated range-edit payload. Jefferson does not establish native `isize` truncation or ZERO-tail semantics: those remain framework/spec evidence. See the final receipt recorded below when the source-bound gate completes.

The primary implementation references are Linux [gc.c](https://github.com/torvalds/linux/blob/master/fs/jffs2/gc.c) (metadata, data and hole relocation) and [readinode.c](https://github.com/torvalds/linux/blob/master/fs/jffs2/readinode.c) (version reconstruction and final inode size). This offline protocol conservatively emits complete logical coverage rather than copying arbitrary raw histories and assuming that erasure leaves reconstruction equivalent.
