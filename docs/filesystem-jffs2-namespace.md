# JFFS2 namespace continuation design

This document describes the additive offline namespace implementation beyond the original one-node replacement/GC checkpoint. The original restricted checkpoint receipt remains historical; the additive native profile and current source-bound receipt are recorded below. Existing journal geometry, caller binding, checked ranges, NOR replay, full-image hashes and durable COPIED-before-erase rules stay in force.

Create authors one complete regular-file, empty-directory or unfollowed-symlink inode under explicit native metadata, then one new name. Hardlink adds one new name for an already reachable regular file or symlink; directory hardlinks are forbidden. Unlink publishes one higher-version tombstone, preserving any remaining hardlinks; removing a nonempty directory is forbidden. Rename/move retains the native inode, requires an absent destination, publishes the destination first and the old name's tombstone last. These are offline journal transactions: a native reader can observe intermediate duplicate names or directory aliasing, and strict reopening requires exact bound-intent recovery after interruption. No mount-visible atomic rename or rollback is claimed.

Preflight and recovery validate operation-specific record counts/types, parent membership and versions, exact byte-name changes, unchanged inode payload/raw metadata for namespace-only operations, explicit metadata for creation, and exact reachable-inode deltas. Destination collision, source/target identity changes, directory hardlinks, root movement and cycles fail before writes. Final whole-image decode/audit alone is insufficient for a move cycle because a detached cycle could become unreachable; the old reachable directory/object set must also survive rename/link/create as specified. Existing deletion histories are retained and newer publication versions must exceed both inode and dirent versions.

Live symlink GC extends the reader only to complete historical NONE symlink nodes: every retained version must have offset zero, csize/dsize/isize equal, 1..254 exact non-NUL target bytes and a unique increasing version. Latest complete target wins. Fragmented, ZERO/compressed, invalid or duplicate-version histories remain unsupported. GC relocates that exact complete target under a higher native version while retaining symlink inode identity and hardlinks; no target is followed.

Acceptance requires independent both-endian raw fixtures, byte names, nested topology/cycle and hardlink cases, rehashed malformed intents with zero target/journal writes, every program/journal/flush cut, independent retain/discard volatile persistence combinations, interruptions during recovery followed by restart, and independently generated mtd-utils histories with completed-state CRC/native extraction oracles. Native oracle limitations from the frozen checkpoint still apply. Physical NOR/NAND and generalized multi-node mutation remain separate work.

The portable editor suite covers namespace creation, cross-parent move, remaining and last-link unlink, non-UTF-8 names, explicit metadata, stale/foreign identity rejection, collisions, invalid names, nonempty directories and parent-under-descendant cycles. Checksum-recomputed intents with unsupported operation tags, regressed publication versions and nonexistent parents reject before either target or journal writes. Create/link/unlink/rename are cut at every program/journal/flush boundary, with four independent retained/discarded volatile target/journal combinations; the recovery process itself is cut and restarted across the same combinations. Repeated COMPLETE recovery is read-only. Both-endian raw symlink histories prove latest complete target selection and live inode GC. Live symlink GC is also cut at every mutation and recovery program/journal/flush boundary under the four volatile-persistence combinations; fragmented, size-mismatched, ZERO and NUL histories reject.

Allocation is deliberately conservative: records append into pristine erase blocks, rather than packing live free gaps. Every transaction retains an exact external journal and source binding, full baseline/final digests and operation-specific semantic proof. Journal operation codes 1/2 remain replacement/GC; 3/4/5/6 are create/rename/unlink/link. Native inode IDs remain stable across links/moves/GC; editor-scoped identities must be reacquired after every committed generation. New inode numbering exceeds all historical native inode numbers and the retained editor floor.

Primary implementation references are Linux [directory operations](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/dir.c) and [GC](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/gc.c), alongside the reader's CRC/layout ledger. The consulted files are archived at `/data/cache/partmgr-jffs2-spec`: `dir.c` SHA256 `8a25c8e8305ef208f16c454dc3568b65263d41951d168f1a053c5ae07f4b3a62`, `gc.c` SHA256 `cf45087b6f7dc6cdd38d20f19deb912f4334cb3f436fe3e8d777244ddb9abffc`. Native lookup selects the highest name version and ignores inode-zero deletions; the kernel symlink creator limits target bytes to 254. Our offline external-journal protocol adds stricter bounded recovery and publication rules and does not claim to duplicate mounted-kernel concurrency semantics.

The explicitly enabled native gate uses mtd-utils 2.3.1 to generate an independent base and incremental history, then declares additional erased FF capacity (1 MiB total, 64 KiB erase, 4-byte program, LE). The raw target sits at byte offset 8192 with unchanged A5/5A framing. Existing append/shrink and partial-erase recovery checks remain; the additive sequence creates a directory and file, moves that file into the directory, creates a hardlink, unlinks the moved name, creates an unfollowed symlink, then relocates its live inode and erases its source block. `jffs2dump` independently validates the completed node CRCs; `jffs2reader` independently extracts the surviving `/alias` payload. The framework checks exact symlink target bytes and a clean full namespace audit. These oracles do not independently prove kernel rename atomicity, all hardlink names, symlink interpretation or recovery after physical power loss.

The final source-bound receipt is `/data/cache/partmgr-jffs2-namespace-native-final2/jffs2-owned-nor-append-gc-v1.txt`, whose embedded profile is `jffs2-owned-logical-nor-namespace-symlink-gc-v2`. The legacy receipt filename is retained for gate continuity. It retains baked/live source equality (including the private namespace module), exact tool arguments, source/input/output/tool/test-binary hashes and end-of-run source/tool/executable revalidation. The compiled test executable is copied to `/data/cache/partmgr-jffs2-namespace-final-test` to avoid concurrent Cargo replacement; its actual enabled invocation is recorded in the receipt. Reader and deterministic builder regression gates also pass at `/data/cache/partmgr-jffs2-reader-namespace-final/jffs2-logical-nor-none-v1.txt` and `/data/cache/partmgr-jffs2-builder-namespace-final/jffs2-direct-tree-builder-v1.txt`.

At this namespace checkpoint, checks were `cargo fmt -- --check`, all-target/all-feature locked Clippy with warnings denied, and the complete all-feature locked host suite (17 editor tests). `TMPDIR=/data/cache/partmgr-jffs2-tmp` is used because the host `/tmp` filesystem exhausted its space; this changes temporary-file placement, not persistence assumptions. This completes the declared bounded offline namespace continuation. The subsequent [file-edit continuation](filesystem-jffs2-file-edit.md) adds inode-preserving multi-node range/length edits. Destination-overwriting rename, mounted-kernel concurrency, multi-node GC packing and hardware/NAND support remain later roadmap work.
