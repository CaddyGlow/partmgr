# Offline JFFS2 logical NOR reader

`fs_jffs2`, `fs_jffs2_audit`, and `fs_jffs2_tree` implement the `jffs2-logical-nor-none-zero-v1` immutable profile. The default entry point retains this strict profile. An explicit [RTIME/ZLIB reader](filesystem-jffs2-compression.md) adds validated compressed regular-file nodes. Offline [authoring](filesystem-jffs2-builder.md), [append/recovery](filesystem-jffs2-edit.md), [range editing](filesystem-jffs2-file-edit.md) and [GC](filesystem-jffs2-gc.md) have separate constrained contracts; kernel mounting and hardware recovery remain unproven.

Callers declare `FlashGeometry` and `Jffs2Endian`. Accepted images consist of complete power-of-two erase blocks of at least 4096 bytes, erased value `0xff`, clear-bits programming, and a declared power-of-two program alignment of 1, 2, or 4 bytes. `FlashLayout::LogicalNor` is mandatory. No page/OOB/ECC, NAND bad-block remapping, byte order, or erase geometry is guessed. Supply a bounded `DiskView` for a filesystem inside a larger source.

The primary format references are Linux's [JFFS2 node definitions](https://raw.githubusercontent.com/torvalds/linux/master/include/uapi/linux/jffs2.h), [scan implementation](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/scan.c), [inode reconstruction](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/readinode.c), and [fragment reconstruction](https://raw.githubusercontent.com/torvalds/linux/master/fs/jffs2/nodelist.c). JFFS2 uses the reflected IEEE CRC32 with initial state zero and no final complement. The header checksum covers its first eight bytes with `NODE_ACCURATE` restored; inode node CRC covers bytes 0–59, payload CRC covers stored bytes, and dirent node/name CRCs cover bytes 0–31 and the native name respectively. Native fields follow the explicitly selected endian. Four-byte node alignment and declared erase boundaries are checked.

Active inode, dirent, canonical 12-byte erase-block-leading cleanmarker, and padding nodes are supported. Uncompressed nodes require equal stored/logical data sizes. Explicit zero-compression nodes require no stored data and reconstruct zeros. Other active compression algorithms, summary nodes, xattrs/xrefs, special/device inode types, old magic, and unknown node types fail explicitly. Malformed headers, nodes, names, data CRCs, and erase-boundary crossings fail; the reader does not copy the kernel's damaged-media resynchronization behavior. Explicitly obsolete nodes are skipped only after their normalized header CRC and bounded node length validate; obsolete node payloads are not certified.

Inodes are ordered by native inode/version. Newer fragments replace overlapping older fragments; gaps read as zero, and the highest-version inode's `isize` bounds the final map, matching the kernel's final truncation step. Earlier inode metadata does not establish an independently replayed operation history. Duplicate versions, including possible GC copies, are rejected until an equivalence profile is implemented. Dirents resolve by parent/exact native name/version; inode zero deletes a name. Version-zero dirents generated by `mkfs.jffs2` are accepted. Names remain byte strings, including non-UTF-8 bytes. The latest applicable directory dirent timestamp adjusts interpreted directory modification time without modifying retained raw inode bytes. A missing inode 1 receives explicitly synthetic kernel-compatible root defaults. Other missing parents fail.

Regular files and directories are supported. Symlink histories require every version to be a complete uncompressed node of 1–254 bytes, with offset zero and equal compressed/data/inode sizes; the latest complete target wins. Fragmented, ZERO/compressed or duplicate-version histories are unsupported; TreeSource exposes the exact unfollowed target and rejects embedded NUL. Symlinks are not ordinary file streams. Hardlinks share source-scoped native identities. Identity scopes use reserved high word 10 and a checked per-open counter; the latest accepted inode version is the generation. Different opens are separate sources.

`Jffs2ReadLimits` bound scanned bytes, nodes, distinct inodes, reconstructed fragments, total native names, and work. Scanning validates data CRCs with 32 KiB scratch and retains metadata/maps rather than file contents. Reconstruction explicitly charges each visited fragment against work, including overlap replacement; there is no uncharged quadratic traversal. Shared memory reservations cover peak node/name/map inventories and scratch, and remain alive through cloned deferred file handles. File reads use an indexed map and retain the original source and resource context. Both original and per-operation cancellation and backing length are checked even for zero-only reads. Provenance/read-budget/sparse queries forward to the underlying `ReadAt`. Actual source errors retain their cause. Stability is `CallerGuaranteedStable`, not a snapshot or byte-change detector.

The audit traverses every live reachable directory and checks target existence, native type agreement, and directory aliases/cycles. All accepted active node payload CRCs were checked during the complete scan. Valid unreachable historical inode numbers are counted separately: deletion intentionally leaves such history, so these are not falsely classified as lost allocation. Bounds or unsupported features return an error rather than a falsely complete report. A namespace defect suppresses every free range. Only whole erase blocks containing erased bytes throughout are reported as informational free ranges; cleanmarker-bearing and partially erased blocks are excluded. This audit provides no physical erase/discard or GC authority and does not establish recoverability of a interrupted append.

Metadata retains native UID/GID byte encoding, full mode, second-resolution Unix timestamps, flags, and exact latest inode header as opaque bytes. Creation time and security/xattrs are absent in this accepted profile; directory synthetic defaults and raw inode metadata are distinguished. Opaque headers have no transplantation guarantee. Deferred streams and metadata allocations remain budgeted.

Portable tests independently construct LE/BE nodes and exercise overlapping versions, truncation, explicit zeros, deletion, hardlinks, non-UTF-8 names, symlink metadata, checksums, caps/refunds, malformed namespace, cancellation, stale backing lengths, and causal read failures.

The native gate is explicitly ignored by default and fails if enabled without tools or evidence location:

```sh
JFFS2_TOOLS=/path/to/mtd-utils/bin \
JFFS2_EXTRACTOR=/path/to/jefferson \
JFFS2_EVIDENCE=/fresh/durable/directory \
cargo test --all-features --locked --test fs_jffs2_native -- --ignored --nocapture
```

It uses mtd-utils 2.3.1 to author LE/BE 256 KiB images with 64 KiB erase blocks, an ordinary 90013-byte multi-node payload, nested directories, hardlinks, and a symlink. `jffs2dump` independently inspects nodes/CRCs, and independently reports a deliberately corrupted payload CRC which the reader also rejects. Jefferson 0.4.8 independently extracts payload and symlink target for comparison. The reader separately proves hardlink identities; Jefferson keeps one dirent per inode and therefore does not independently prove both hardlink names. Its UTF-8 name decoding also cannot independently certify non-UTF-8 names; those are covered by the separate raw portable fixture. Version overlap, deletion and truncation currently have portable/spec-based evidence, not a kernel-mount oracle. Raw framing at offset 8192 is checked byte-for-byte unchanged. The receipt retains exact argv, tool/dependency versions, executable/extractor-source/image/payload SHA256 values and interpretation. Supplying `JFFS2_SPEC_ARCHIVE` retains the consulted kernel header and four implementation references with SHA256 values in the receipt. No native mount, NAND behavior, writes, GC or power-loss claim follows from these checks.
