# Owned APFS COW editing

An explicit registry-storage gate now covers the supported range profile in
GPT/MBR raw and QCOW2 images. Set `PARTMGR_APFS_EDIT_RAW` to a directory with
native-checked three-file `gpt.raw` and `mbr.raw` fixtures, and
`PARTMGR_APFS_EDIT_CONTAINER_EVIDENCE` to an absent output directory. Run the
ignored `apfs_edit` storage-consumer test with the explicit development override
for the partmgr checkout under test. Enabled missing native tools fail the gate.
Each case inspects the actual partition boundary, retains the exclusive writer,
durably saves the recovery anchor, modifies DATA across a block boundary,
reopens a complete allocation audit and validates all DATA/resource-fork bytes
with native extraction. Partial boot publication persists31 bytes before an
injected error; cold recovery must produce the same whole logical image as
normal publication. Container conversion and unchanged outer framing are
independently checked. The frozen eight-case receipt is
`/data/cache/partmgr-apfs-writer-native-v3-1f5uggh5/root-audit.json`; broader
writable trees and hardware durability remain separate requirements.

`ApfsEditor` owns exclusive `Storage` and supplies bounded native create-file/create-directory, whole DATA replacement, positional range replacement, truncate/extend, regular hardlink, rename/move and unlink operations, with restartable native checkpoint recovery. All operations share one fresh-checkpoint assembler. This initial profile does not complete the writable APFS family target: reclamation, snapshots, cloned/shared-stream mutation, broader B-trees and multi-volume editing remain required work.

The initial write profile requires one unencrypted case- and normalization-sensitive volume, a single allocation chunk of at most 128 MiB, single-leaf native metadata trees, no snapshots, no shared clone streams, no external resource streams, validated retained retirement queues and enough unused checkpoint/internal-pool slots. Regular hardlinks and inline resource forks are preserved through modification. Removing the last native link removes its resource-fork metadata and retires its DATA allocations; removing one alias preserves the surviving object and forks. Empty-directory deletion is supported; nonempty deletion is rejected. BSD write/security flags gate the operation. Broader reader support does not imply write support. Insufficient resources or unsupported profiles fail during planning before target mutation.

A transaction consumes previously unused descriptor/data/internal-pool slots. Validated prior main/internal-pool retirement entries retain their original XIDs; new retirements are merged without freeing historical ownership. Counts and oldest XIDs cover the full retained queues. Reopening does not authorize reclamation. Expanded descriptor/data rings permit two transactions in the single-chunk profile, whose native internal pool is exactly six blocks; a third transaction exhausts unused internal-pool slots and is refused before writes. Arbitrarily enlarging that pool would violate native chunk/CIB/CAB topology and is rejected. More transactions require genuine broader topology or validated reclamation, which remain required work. Successful publication permits inspection through fresh owned generations, not reuse of old plans or handles.

`Storage` is never implemented or wrapped as immutable `ReadAt`. Decoder input is a separately owned immutable map of copied metadata blocks. Only a typed missing-block sentinel permits another copy and decoder restart. Real I/O, malformed structures, unsupported features and cancellation propagate unchanged. Ordinary payload is not prefetched. Each preparation attempt charges the declared reader and audit work ceilings, plus snapshot reads and actual storage copies or binding reads. `metadata_blocks`, `attempts` and `work` are explicit independent limits. Memory for copies and both live index tables is reserved before allocation; decoder/audit allocations retain their shared leases.

Preparation requires a complete clean all-volume and retained-checkpoint allocation/reference audit. The session retains exact length, selected XID and copied metadata bytes. Revalidation checks the original owning cancellation token and operation token, including EOF. Owned identities use domain 17 and a checked local generation; immutable APFS identities retain domain 16. A successful commit invalidates prior owned handles. Returning storage consumes the session and releases retained leases.

`plan_range`, `plan_create` and `plan_replace` retain the input `FileRead`, exact identity and length and binds every short read to those values. Range replacement copies touched old payload blocks or materializes holes and preserves logical EOF. Creation/replacement validates a complete bounded source extent inventory and preserves whole-block source holes; unwritten source extents are rejected. Truncation removes excess current mappings, and extension creates holes while COWing any old partial EOF block so old uninitialized tails never become logical data. Every freshly written physical EOF tail is zeroed. Native write-generation, written-byte, sparse-byte and allocation counters are maintained. Replacement/truncation retain native timestamps, other inode attributes, names, sibling records and inline resource bytes. An immutable projection must pass the complete native audit before writes begin. Fresh payload and metadata allocations are proved free across retained history; old checkpoint metadata and replaced data remain allocated through native main/internal-pool free queues. Reclamation is not implemented.

`ApfsCreateMetadata` requires explicit permission bits (0..=0o777), UID, GID and native unsigned nanoseconds since Unix epoch. New objects use those native values; file type is supplied by the operation. Names retain exact UTF-8 bytes and the native terminating-NUL encoding, without case folding or normalization. Empty, slash/NUL, dot/dotdot, invalid UTF-8 and over-255-byte names fail before writes. Destination collisions fail before writes. Rename/move preserves directory addition times and inode timestamps, changes the native primary name/parent as needed and rejects directory ancestry cycles. Hardlink/unlink maintain native directory, sibling-link and sibling-map records, stable existing sibling IDs, checked new identities and native link/child/file/directory counters. Unrelated metadata is retained. Root/private system-directory mutations and BSD write/security flags gate unsupported operations.

`directory_identity`, `file_identity` and `directory` return identities bound to the owned source and local generation. `ApfsMutationPlan` is the common source-bound plan type, and `commit_mutation` uses the same publication protocol as `commit_range`. Any recovery-required owner fences identity lookup, directory enumeration, reads and planning. The caller retains exclusive storage authority; identities confer no independent write authority.

The caller must retain `recovery_anchor()` durably before passing it to `commit_range`. Its 96-byte encoding binds trusted geometry, UUID and explicit volume OID; SHA-256 detects anchor damage and does not authenticate untrusted images. The anchor is necessary when a torn block-zero update cannot provide trustworthy geometry.

Publication has five flush/readback stages: new payload; new object-map/catalog/extent/spaceman metadata; checkpoint ephemeral objects and map; terminal checksummed NX checkpoint; then block-zero selected-checkpoint hint. The terminal checkpoint is the native publication boundary. A complete current/history audit follows publication before block zero is restored, and another audit follows restoration. Any possible mutation failure fences the owner into recovery-required state. An external undo journal does not replace this native COW protocol.

`recover_with_anchor` uses retained geometry to inspect bounded native checkpoint descriptors, selects and fully audits the highest complete supported checkpoint, and restores only the selected block-zero hint. It never derives geometry from torn or checksum-invalid block zero. Unsupported higher state fails rather than silently selecting older supported state. Interrupted hint restoration is repeatably recoverable with the same anchor. Native history is preserved; recovery does not claim reclamation or journal replay.

Independent tests cover preparation without payload reads or mutation, stale bindings, actual I/O errors, malformed metadata, caps, cancellation and lease refunds. Operation tests cover exact Unicode names, explicit creation metadata, zero-length creation/replacement/truncation, sparse data, EOF tails, hardlinks, file/directory rename, move, last-link file/fork removal and empty-directory removal. Fault tests exercise every native block-stage boundary, interior torn checkpoint/boot writes and all five barrier failures across four write/failed-flush persistence models for all named operations; cold restart produces complete exact old or exact new occurrence/inode/DATA/fork signatures. Stale input identities, original-owner cancellation, target changes, prewrite memory exhaustion, post-publication shared-pool exhaustion and deferred input failures retain their declared errors or fence into native recovery, then refund leases. Recovery itself is tested under torn restoration and damaged-anchor refusal. Independent raw free-queue fixtures validate ghost and explicit retirement lengths, duplicate/future/current-owner/free-bit rejection and free-range exclusion.

The retained enabled native namespace gate `/data/cache/partmgr-apfs-edit-namespace-native-v4` passed thirteen separately framework-built 64 MiB images through Linux apfsprogs 0.2.1 `apfsck -c -u -w` and TSK 4.14.0 explicit current-volume payload/resource extraction and inode name/link checks. Cases are: 0 create sparse Unicode file, 1 create directory, 2 full replacement, 3 shrink, 4 extend, 5 hardlink, 6 rename, 7 move, 8 remove one alias, 9 remove last-link child, 10 rename directory, 11 remove empty directory, 12 remove last-link file with resource fork. Fixture cases 11/12 explicitly construct an empty Box or omit its Alias occurrence before initial image authoring; they do not mutate a preformatted template. Each publication injects and flushes a31-byte prefix of the new block-zero hint, saves the corrupted block, requires an independent Apple Fletcher mismatch and native checker rejection before recovery, drops the old owner, cold-reopens with its retained anchor, audits the selected complete checkpoint and restores the hint before successful native validation. This file-backed fault injection is not a host power-cut experiment.

The portable cut gate `/data/cache/partmgr-apfs-edit-namespace-portable-cuts-v2` retains fourteen embedded production/core/storage/independent-fixture/test source files, a fixed executable, execution log, per-operation cut lists and old/new signature hashes. Its twelve operation variants cover1608 scenarios across the four persistence models, with source/archive/binary correspondence verified before and after execution. This portable failure model remains separate from the file-backed native oracle and macOS evidence.

Each native case archives compiled source bytes and fixed test executable, binds tool/source/binary hashes before and after commands, records tool version outputs and a durable anchor, and verifies validators leave the image unchanged. Directory names also undergo exact framework lookup; TSK's hashed-versus-unhashed directory-name limitation remains documented in [filesystem-apfs-builder.md](filesystem-apfs-builder.md). Native inode primary names, creation ownership and link counts are checked separately. The normal range receipt `/data/cache/partmgr-apfs-edit-native-v5` is historical exact-source evidence; namespace v1 failure, normal-operation v2 and partial-write/cold-reopen v3 evidence remain retained. In v3, the2048-byte prefix could already contain all changed NX fields, so checksum-invalid boot recovery was not established by that receipt; v4 supplies the explicit negative control. These are Linux experimental-tool checks for this initial profile, not macOS mount/fsck, reclamation, snapshot, shared-clone or full-family writable acceptance.

Primary definitions are Apple's [Apple File System Reference, 2020-06-22](https://developer.apple.com/support/apple-file-system/Apple-File-System-Reference.pdf), especially checkpoint/mounting and space-manager/free-queue definitions, and the pinned [apfsprogs 0.2.1 space-manager checker](https://github.com/linux-apfs/apfsprogs/blob/v0.2.1/apfsck/spaceman.c). The frozen [offline builder](filesystem-apfs-builder.md) is a separate operation.

Repeated publication is additionally checked against an independent enlarged-ring image and framework-authored expanded rings. Native repeat evidence retains two consecutive create/replace checkpoints, native checker acceptance and independent TSK full payload bytes. Second-transaction failures at all five barriers cold-recover exact old/new payloads in an immediately durable-write model; this does not extend the four-model exhaustive single-transaction cut claim to repeated publication. Failed enlarged-pool native attempts are retained and establish no acceptance.

The repeat checkpoint is retained at `/data/cache/partmgr-apfs-repeat-native-v7`: 20 exact embedded/archived compiled sources, fixed executable, start/end executable and native-tool hashes, two framework-authored checkpoints, checker logs, explicit volume-block TSK commands and complete expected/extracted payloads. The same retained executable runs the five portable repeat controls. Earlier v1/v2/v3 failed attempts remain separate. Native pool validation also corrected the independent five-chunk fixture to an 18-block pool, relocated away from second-volume metadata; its allocated count is 69. The previous six-block five-chunk fixture was invalid and cannot support a native-format acceptance claim.
