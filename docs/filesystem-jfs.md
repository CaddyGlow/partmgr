# JFS immutable reader, allocation audit, and native tree

`JfsVolume` reads actual Linux JFS structures and indexes deferred payloads. `audit_jfs` proves allocation and namespace consistency within the accepted profile; `JfsTreeSource::inventory` requires that complete clean proof before publishing a common tree. These are read-only operations and confer no repair or write authority. Source domain 15 identifies each independently opened source. The caller must keep the underlying source immutable: length checks and bounded metadata rereads cannot detect arbitrary same-length concurrent writes.

The initial accepted profile is Linux version 1 or 2, 4096-byte filesystem blocks, a clean aggregate and an inline log whose header is `LOGREDONE` with no active users. The reader checks both aggregate superblocks, aggregate inode table copies, primary and secondary inode-map locations, the fileset inode map, and working/persistent allocation maps. Version 1 does not define the trailing superblock UUID fields; UUID correspondence is required only for version 2. A clean superblock alone is insufficient. No journal replay is attempted.

Current bounds require allocation-control level zero, 8192-block allocation groups, one aggregate IAG with its fixed 32-inode extent, and one fileset IAG with at most 4096 inodes. Inode maps must occupy one contiguous two-page mapping. Fileset directory cursors must fit the twelve inline persistent index entries. Directory B+tree and extent B+tree external pages are supported, including bounded child depth, sibling chains, self addresses, key ranges, leaf ordering, slot partitioning, continuation chains, and checked physical extents. Populated higher allocation-control levels, additional IAGs, external persistent cursor tables, or inode-map growth profiles return `Unsupported`. This is an initial profile, not completion of the full JFS family destination.

Native names retain exact UTF-16 code units, including unpaired surrogates. Lookup uses exact code-unit equality; it does not claim Linux case-folding or Unicode normalization equivalence. Native inode number and generation form object identity. Regular hardlinks retain the same object identity. Directory parents, references, link counts, reachability, and cursor-to-leaf locations are checked independently of file payload decoding. POSIX mode, native UID/GID, and native seconds/nanoseconds are mapped explicitly; raw inode/security provenance remains available as opaque metadata. ACL/EA descriptors, symlinks, special files, unsupported extended flags, compressed/COW/transient extent flags, and nonempty reserved fileset payloads are rejected instead of omitted. JFS has no HFS-style resource-fork projection in this profile.

Indexed regular files expose recorded data, holes, and allocated unwritten extents. Holes and unwritten logical bytes read as zeros. Full physical extent allocation, including bytes beyond logical EOF, remains available to the audit. Opening a file does not read its complete payload. Local opening verifies that payload allocation is marked allocated and does not overlap system allocation or any indexed metadata page.

`JfsReadLimits` caps blocks, inodes, directory entries, tree pages, extents, and work. `JfsAuditLimits` caps blocks, objects and occurrences, depth, work, and findings. Allocation is charged to shared `Resources` before proportional structures are built. Volume, tree, file maps, directory pages, metadata, and reports retain their leases until dropped. Cancellation applies at opening, indexing, auditing, and payload reads, including EOF. Source read errors are preserved. Tree cursors bind source, generation, directory identity, and position. Deferred files remain valid after dropping the caller’s volume handle because they retain the source and indexing leases.

The complete audit accounts for fixed aggregate structures, system inode maps, allocation-map tree pages, inode extents, directory and extent metadata pages, recorded and unwritten payload extents, bad-block inode allocation, and reserved fsck/log tails. It checks bitmap ownership, crosslinks, allocation without owners, references, mirrors, and native block counts. Any finding suppresses all free ranges. Free ranges are restricted to mapped allocation blocks; reserved tails and metadata are never offered as free. Unsupported or uninspectable profiles fail rather than produce a partial free-space proof.

## Independent evidence

The byte-backed fixture constructor in `tests/fixtures/jfs_clean.rs` is independent of the decoder. It builds native endian structures and recomputes allocation buddy summaries directly from allocation bits. Ordinary tests cover malformed geometry and log state, mirrors, working/persistent map disagreements, inode maps, buddy summaries, invalid extent addresses and cycles, malformed directory slots and cursor references, local versus complete ownership checks, lost allocation, hardlinks, sparse/unwritten reads, bounds, cancellation, I/O failures, source-length changes, caps, and resource refunds.

The opt-in ignored test `native_formatter_checker_and_debugger_receipt` requires `PARTMGR_JFS_NATIVE_EVIDENCE` naming a fresh directory, jfsutils 1.1.15, and Sleuth Kit 4.14.0. Missing tools fail the enabled gate. It formats a disposable 64 MiB image using `mkfs.jfs`, verifies the blank filesystem using `fsck.jfs -n`, and inserts the independently authored inode/namespace/extent fixture into that formatter’s actual structures. The insertion includes a nested directory, two hardlinks, a sparse file, unwritten allocation, and an external extent and directory leaves. `fsck.jfs -n` verifies allocation and references after insertion; `jfs_debugfs` independently decodes directory and inode output. Image hashes remain unchanged across validators. The reader proves 349 allocated blocks including reserved tails and verifies expected deferred payload bytes.

The gate captures compiled-in engine/fixture/test bytes and checks their hashes against the running source before native commands, along with the test executable and all tool hashes. It rechecks every binding at the end. Commands, exit statuses, stdout, and stderr are separate artifacts. The passing isolated checkpoint is `/data/cache/partmgr-jfs-native-v6`; its source correspondence applies to the captured files, not subsequent edits.

Sleuth Kit 4.14.0 rejects the explicitly attempted JFS filesystem type. That negative capability evidence is retained; it is not an independent payload oracle. `jfs_debugfs` display truncates an unpaired surrogate and is not an exact Unicode-name oracle. Whole-file bytes are compared with the known independently authored insertion bytes, not an independent native extractor. Native mounting, macOS or Windows compatibility, broader case-folding behavior, multi-IAG and large directory cursor tables, external logs, journal replay, EA/ACL and special-file profiles remain unestablished.
