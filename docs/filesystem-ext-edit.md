# Recoverable classic ext2 editing

`fs_ext_edit::ExtEditor` owns the target `Storage` and external undo journal. The caller supplies a checked bounded region and volume/generation binding and must independently establish physical disjointness of journal and target, including underlying aliases. Owning two handles cannot establish that fact. Immutable `ExtVolume` retains `ReadAt`; mutable storage uses a distinct borrowed decoder and never becomes an immutable payload source.

Opening requires a complete clean allocation/reference audit in the same exclusive session. The classic profile covers 1/2/4 KiB blocks, 128-byte Linux inodes, direct/single/double/triple indirect mappings, regular files and directories. Journals, extents, xattrs, unsupported flags, allocated symlinks and special files remain explicit audit gates. The reader/tree can inventory supported symlinks without authorizing this editor. The target must remain exclusively controlled throughout; length checks cannot detect concurrent writes.

Reviewed operations include existing-file range replacement, extension from a positional `FileRead`, truncation, file/directory creation, exact-byte rename/move, unlink and empty-directory deletion. Sparse replacement allocates zero-initialized pages without changing size. Extension preserves the old prefix and checks source identity/length around every short read. Truncation disconnects references before releasing verified ownership, zeros retained allocated tails and clears pointers at zero length. Owned empty indirect nodes within EOF can remain; nodes beyond truncated EOF are released.

Names are exact 1–255 native bytes excluding NUL, slash, `.` and `..`. There is no case/encoding transformation or implicit destination overwrite. Directory growth initializes pages before publication. Moves update actual `..` records and parent links, reject descendants/cycles and preserve the moved inode. Unlinking a hardlink retains shared content; final unlink frees only verified owned blocks and inode. Deletion is nonrecursive and requires explicit nonzero native deletion time.

Creation takes an exact 128-byte metadata template: managed size/link/allocation/pointer/generation/deletion fields must start zero. Supported owner, mode, native atime/mtime/ctime and other supported bytes are copied exactly. `zeroed(mode)` specifies numeric UID/GID zero and native Unix timestamp zero, not unknown metadata. Allocation assigns a checked next native inode generation. Existing times/owner/mode/generation remain exact; reports identify size/allocation/namespace/link/deletion changes. No current time or owner is guessed. Large files require the native large-file feature already enabled.

Planning charges shared resources, bounds work/affected bytes/directory entries/file blocks/journal body and patch counts, checks cancellation, rejects physical overlaps and audits the complete prospective patched state before mutation. Plans contain changed ranges and initialized allocations, not whole-image rewrites. All successful or failed commits invalidate old session handles through a checked generation increment. Failed mutation enters `NeedsRecovery` and drops old audit authorization; recovered reopening changes source scope.

## Ordering and recovery

The complete external v1 undo body is durably published before target mutation. The primary superblock is then marked unclean, flushed and read back. Stages initialize pages, allocate bitmap/counters, publish references, and release detached allocation. Every stage is flushed and verified before advancing. A complete prospective audit with only state masked clean precedes final clean publication. Mutable state/counters are maintained in the primary superblock; ext2 backup superblocks retain native backup semantics, without a claim that all backups contain current live counters.

Recovery validates the complete journal digest/body/ranges and exact saved clean-state fence, even when counters sort before the fence. Validation and cancellation complete before restoration. Restoration keeps the target unclean, restores/verifies saved ranges, audits restored ownership, then durably publishes clean state before journal rollback completion. Invalid/foreign/truncated journals cannot authorize writes. Only a live owner that proves no target write was attempted can discard an unpublished journal; restart cannot infer this from malformed bytes.

These choices follow [Linux ext2 documentation](https://cdn.kernel.org/doc/html/latest/filesystems/ext2.html), [Linux ext2 structures](https://github.com/torvalds/linux/blob/master/fs/ext2/ext2.h), and kernel descriptions of the [superblock](https://cdn.kernel.org/doc/html/latest/filesystems/ext4/super.html) and [classic inode fields](https://cdn.kernel.org/doc/html/latest/filesystems/ext4/inodes.html).

## Validation

Independent byte fixtures check full-container patch projections and framing, sparse initialization, hardlinks, metadata, stale/foreign handles, bounds/cancellation/refunds, indirect extension, zero-length reallocation, directory growth and move cycles. Every-write/barrier models include partial-prefix failures, same-owner recovery and restart retaining or discarding volatile writes.

The ignored native gate requires every tool and a fresh destination when enabled:

```sh
PARTMGR_EXT_EDIT_EVIDENCE=/absolute/fresh/destination cargo test --all-features --locked --test fs_ext_edit native_ext2_all_operations_every_io_cut -- --ignored --nocapture
```

It uses `mke2fs -t ext2 -I 128 -b 1024/2048/4096 -O none,filetype,sparse_super`, independent `debugfs` writes/hardlinks/directories/sparse punching, a deterministic 131089-byte payload and native directory growth. Each operation/failure cut compares the whole container with original or exact approved patches and runs read-only `e2fsck -fn` after recovery. `debugfs dump` checks committed content independently. Receipts retain source/binary/tool/image/payload hashes, exact commands and outputs. This models regular-file IO failures, not physical power loss or firmware. Passing receipt details will be recorded after final source freeze; earlier runs remain historical snapshots.
