# FAT allocation and volume-state audit

`fs_fat_audit::audit_fat` is a read-only FAT12/16/32 inventory over an immutable `ReadAt` source. It inventories every addressable selected-FAT data entry and walks the reachable namespace with explicit cluster, object, per-directory slot, diagnostic and shared memory bounds. Retained maps and reports keep their budget reservation; cancellation is checked during inventory and traversal. Exhausted bounds, backend errors and strict namespace decoding errors return an error without a partial report.

The audit detects cross-object allocation, chain cycles, free/bad/reserved/out-of-range chain transitions, file-length mismatches and unowned nonfree allocation. Directory allocation is followed through its EOC even when a namespace terminator appears earlier. FAT32 root allocation participates in ownership. Namespace directory recursion becomes a crosslink and is bounded. Bad-cluster markers are unavailable space rather than lost allocations.

Mirrored FATs are compared over entries zero, one and all addressable data entries; unused FAT capacity is outside this scope. When FAT32 mirroring is disabled, only its declared active FAT controls allocation and state; inactive copies are deliberately excluded. FAT16 and FAT32 entry-one clean-shutdown and no-hardware-error bits are reported independently. FAT12 has no equivalent flags. FAT32 values are interpreted using their low 28 bits. Selected FAT entry zero must encode the BPB media descriptor in its low byte with the remaining defined bits set. FAT12 entry one must be an EOC marker; FAT16/32 entry one must retain ones in all non-status bits. InvalidReservedEntry reports these defects independently of dirty-state and mirror findings, following Microsoft FAT specification1.03 page18.

`namespace_complete()` is false when an invalid or repeated directory allocation prevents descendant traversal. Such a report exposes defects, not a proof that all descendants have been enumerated. Strict directory syntax, including native name rules, remains the existing `FatVolume` decoder's policy. Dot-link semantics, FSInfo hints, boot-backup equality, payload correctness are outside this audit.

Free ranges consist only of consecutive unallocated, unclaimed data clusters. They exclude reserved sectors, every FAT, the fixed FAT12/16 root, unavailable clusters, and any sector remainder or source/container tail. Ranges and defect-free reports grant no mutation authority: the caller still needs exclusive source control, a writable profile and an explicit durable commit protocol. A defect-bearing or incomplete namespace report must not authorize allocation reuse.

Independent literal BPB/namespace/FAT fixtures cover crosslinks, orphan allocations, dirty state and mirror disagreement, directory-tail cycles after a terminator, recursive directory names, short/free chains, bounds, cancellation and reservation release. These host tests do not establish firmware boot correctness.
