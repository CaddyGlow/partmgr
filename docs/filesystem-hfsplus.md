# HFS+ and HFSX immutable read profiles

`fs_hfsplus::HfsPlusVolume` opens actual bare HFS+ version 4 and HFSX version 5 volume headers, indexes native catalog objects and allocation extents, and exposes deferred positional data and resource forks. `fs_hfsplus_tree::HfsPlusTreeSource` implements the common tree contract after a complete clean allocation/reference audit. These APIs provide no editing, repair, journal replay or discard authority.

The initial profiles require the selected immutable source length to equal `totalBlocks * blockSize`. This avoids guessing the alternate-header location on volumes with residual bytes outside the allocation blocks. Callers select the exact filesystem region before opening; HFS wrappers, residual partition padding and classic HFS require separate profiles. Reserved startup/header areas and both native header locations participate in ownership accounting.

A checked unmounted bit must be set and the boot-inconsistent bit clear. Journaled volumes and nonzero journal-info references fail explicitly, including clean-looking journaled headers. A signature cannot establish journal consistency. Populated attributes trees, extended-attribute/security flags, compression, hardlink indirection, symbolic links, devices and other special catalog objects are unsupported and fail the operation. Empty attributes trees are structurally validated and their complete physical allocations are owned. Unsupported records are never omitted to obtain a clean or complete result.

HFS+ and case-folding HFSX currently support an explicitly limited ASCII namespace comparator. Non-ASCII keys or lookup components fail `Unsupported`; the reader never substitutes modern Unicode lowercase rules for Apple's historical comparison. HFSX's actual catalog `keyCompareType` selects binary UTF-16 or case folding; `HX` alone does not imply case sensitivity. Binary HFSX keys retain and compare exact native UTF-16 units, including surrogate units. The reader performs no host path conversion or Unicode normalization and does not claim to validate historical Unicode decomposition. The full frozen Unicode comparator remains a separate expansion.

Catalog and extents-overflow B-trees use checked native record-offset tables, node allocation maps, header geometry, ordered keys, index-child lower keys, child bounds/heights, visited-node cycle detection, sibling links, leaf totals and free-node counts. Unreachable allocated nodes fail validation. Header-linked map nodes are bounded and checked too. All native forks retain full allocation extents, including preallocation and physical tails beyond logical EOF. Inline extents and indexed overflow records support both fork types. Missing, orphaned, overlapping-key or out-of-range extent records fail; self-overflow of the extents-overflow file remains unsupported. Bad-block records have explicit allocation ownership and must agree with the native spared-block flag.

`open_fork` creates an indexed map without reading payload, checks bitmap ownership and protected metadata ranges, and clips positional access to logical EOF. Empty reads at EOF still check cancellation and source identity. Handles retain their source, volume indexes and reservations after the caller drops the volume. The source domain is 11, separate from classic HFS. Source length and the retained primary header are checked on access. The caller guarantees unchanged backing bytes throughout inventory and all deferred reads; header/length checks do not detect every same-length payload mutation or create a snapshot.

Metadata exposes catalog timestamps as unsigned seconds since 1904-01-01 GMT, native BSD mode bits, and a big-endian UID/GID pair. Zero legacy BSD fields remain their native values; no host permissions are inferred. Finder information, BSD flags, backup/change dates, text encoding and complete catalog bytes remain opaque metadata requiring a relocation policy. The exact native catalog key retains the implicit root name and parent identity. Unsupported security and attribute profiles fail rather than appear absent. Resource forks are distinct object-owned streams even when empty.

`audit_hfsplus` covers the allocation bitmap, reserved areas, every system fork, bad blocks and every catalog fork's full physical allocation. It checks primary/alternate header geometry and system forks, crosslinks, referenced-free and lost allocations, catalog thread/parent/name/type references, reachability, directory valence and applicable folder counts, global file/folder/free summaries and namespace depth. Free byte ranges exist only on a complete defect-free result and exclude all metadata, reserved areas and source tails. An immutable proof confers no mutation authority and assumes the caller's continued source stability.

Reader limits independently cap blocks, total tree nodes, total leaf records, total extent descriptors and metadata work. Audit limits cap blocks, objects, depth, work and findings. Proportional allocations use checked arithmetic and fallible reservations before construction. Inventories, scratch, reports, pages, metadata and file handles retain/refund their shared memory leases. Cancellation, backend errors, stale identities and cap exhaustion remain explicit failures with underlying I/O causes retained.

Independent ordinary fixtures in `tests/fixtures/hfsplus_clean.rs` encode big-endian structures without any production codec or builder. They include a catalog index and two leaves, a ninth extent in the overflow tree, a resource fork and nested file. Tests cover both native comparators, HFSX case-fold selection, exact surrogate units, EOF, allocation/crosslink/lost/mirror/count defects, malformed child/offset/fork/header fields, independent work/memory caps, cancellation, deferred I/O failures, header/length changes and lifetime refunds.

The enabled Linux native gate uses hfsprogs 627.40.1 to format fresh 64 MiB HFS+ and binary HFSX images. Independent raw fixture insertion updates catalog records, threads, bitmap, overflow-tree records and native summary fields. Required TSK `fls`, `fsstat`, `istat` and `icat` validate actual namespace, free counts, fragmented data, the resource fork and the nested payload. The framework's complete audit agrees with TSK counts and payloads; source and validator hashes remain unchanged around read-only checks. Commands, outputs, executable paths/hashes, source hashes and binary hash are retained. Missing enabled-gate tools fail explicitly.

Linux `fsck.hfsplus` on these regular files exits 8 with `Can't get device block size`, including with `-b 512`. Its attempted read-only checks are recorded as a blocked device-ioctl layer, not a clean result. This gate makes no macOS-native fsck/mount or firmware claim. macOS validation remains required before advertising those environments.
