# Immutable ext3 and ext4 profiles

`ExtVolume` accepts bounded Linux profiles for classic ext2, clean ext3 with an inactive internal journal, ext4 extent maps, and clean default metadata-checksummed ext4. The modern profile validates metadata CRC32C/checksum seeds, 32/64-byte descriptors, flex-group placement, uninitialized bitmaps, native directory indexes, hidden resize/orphan ownership and inline/external xattr containers. The complete allocation audit remains explicit; successful opening alone does not establish whole-volume ownership. Unknown features, required journal/orphan recovery, higher physical addresses, inline data, encryption and casefold remain gates. This checkpoint does not complete the broader ext3/ext4 objective.

The immutable decoder retains its source/generation identity and operation-local metadata cache. Indexed payload handles retain the original uncached immutable source. Borrowed mutable-storage decoding explicitly rejects journal/extent profiles before opening journal maps or permitting editor authorization. The classic new-image builder continues to author its declared classic format. No mutable `Storage` implements immutable `ReadAt`.

## Extent trees

Extent headers, index keys and leaf records are checked before constructing a compact positional index. Validation bounds depth (at most five), child depth/key intervals, record capacities, logical ordering/overlap, 32-bit physical ranges, allocation bitmap membership and filesystem metadata exclusions. Repeated metadata blocks, cycles and physical data/metadata aliases fail closed. Work, metadata/physical allocation counts and shared memory are bounded by caller block caps; cancellation is checked during tree traversal and for every physical block validation. The conservative retained reservation covers worst-case decoding/index storage under that cap.

Initialized extents map to source bytes. Holes and allocated unwritten extents read as zero without inspecting poisoned physical payload. The native length encoding treats 32768 as initialized; larger values represent unwritten length after subtracting 32768. All referenced allocations are retained separately from logical read ranges, so unwritten preallocation beyond EOF remains owned and counted in a whole-volume audit. Initialized allocations beyond EOF are diagnosed by the audit. These rules follow the kernel's [extent-tree format](https://www.kernel.org/doc/html/latest/filesystems/ext4/ifork.html) and [extent validation implementation](https://github.com/torvalds/linux/blob/master/fs/ext4/extents.c).

## Inactive journals

The filesystem must advertise clean state and omit the recovery-required incompatibility bit. Journal inode eight must be allocated, regular, linked once, block-aligned, completely initialized and bounded to 65536 logical blocks. Big-endian JBD/JBD2 v1/v2 superblock magic/type, block size, journal length, first-log position and the 1024-block minimum are checked. A nonzero active-log start or abort error rejects opening. Version two additionally checks internal filesystem UUID binding, one user and the feature allowlist: Inactive revoke and checksum-v2/v3 support are accepted. Checksummed journals require CRC32C type four and a matching whole 1024-byte superblock checksum with its checksum field zeroed. Conflicting checksum modes, checksum-v1, dynamic superblocks, async commits, 64-bit tags, fast commits and unknown flags remain gated. External/nonstandard journals and orphan recovery are unsupported.

A zero journal `s_start` is only one condition and never overrides dirty filesystem state or required recovery. The reader does not replay transactions or infer payload durability from an inactive metadata journal. The audit includes hidden journal data and mapping blocks in ownership/sector accounting while excluding its hidden link from ordinary namespace reachability. See the [kernel journal format](https://www.kernel.org/doc/html/latest/filesystems/ext4/journal.html) and [JBD2 superblock/reset checks](https://github.com/torvalds/linux/blob/master/fs/jbd2/journal.c).

They cover leaf/indexed maps, sparse/unwritten zeros, beyond-EOF ownership, malformed geometry/flags/keys/cycles/aliases, cancellation/refunds and editor rejection without writes. Existing classic cache work counts and reader/audit/editor regressions remain unchanged.

## Extended Linux inodes

The immutable profile accepts 256-byte inodes using their declared stride throughout inode reads, metadata exclusions and whole-volume audit. `extra_isize` must be aligned, within the 128-byte extension, and at least the filesystem minimum for live inodes; minimum/desired superblock sizes are checked. Native nanoseconds must be below one billion. Undeclared nonzero tails and xattrs remain unsupported in the earlier non-checksummed profile; the modern profile validates native xattr containers separately. Exact declared extension bytes are exposed by `raw_extended_metadata()` and retained as opaque tree metadata. Access/change/modification fields retain their native seconds and epoch/nanosecond words; a declared birth-time field is opaque rather than absent. No epoch conversion is guessed. These layouts follow the [kernel inode format](https://www.kernel.org/doc/html/latest/filesystems/ext4/inodes.html).

`ExtGeometry::is_classic()` is false for extended inodes. Borrowed mutable decoding rejects 256-byte inodes before audit or editor authorization. Portable tests independently relocate the inode table, adjust bitmaps/counters, compare positional payload and exact timestamp encodings, and reject malformed sizes/nanoseconds/tails with reservation refunds. The explicit native gate now covers eighteen 128/256-byte profiles plus twenty-four independently assembled checksum derivatives accepted by read-only e2fsck. Modern default-profile acceptance and evidence are described below; this older receipt remains bound to its earlier sources.

## Bounded modern default ext4

The immutable modern path combines bounded 32/64-byte descriptors, global flex-group metadata exclusions, normalized uninitialized bitmaps, CRC32C metadata validation, native directory hash ranges, canonical resize-inode references and inactive orphan-file ownership. Opening the decoder validates every orphan-file block before payload access; its audit validates all allocation and namespace references, including shared external xattr reference counts. ACL/value encodings and xattr deduplication hashes remain uninterpreted; exact native xattr containers are retained as opaque tree attributes and security metadata is explicitly uninspectable.

These checks follow the kernel's [metadata checksum definitions](https://www.kernel.org/doc/html/latest/filesystems/ext4/checksums.html), [descriptor layout](https://www.kernel.org/doc/html/latest/filesystems/ext4/group_descr.html), [directory format](https://www.kernel.org/doc/html/latest/filesystems/ext4/directory.html), [orphan-file format](https://www.kernel.org/doc/html/latest/filesystems/ext4/orphan.html), and [xattr format](https://www.kernel.org/doc/html/latest/filesystems/ext4/attributes.html). The profile bounds setup to 1024 groups and supports 1/2/4KiB blocks, 128/256-byte Linux inodes, and 32-bit physical addresses even when native descriptors are 64 bytes. Higher addresses, EA value inodes, metadata-group layouts, casefold/encryption, large-directory index depth, and overlapping xattr values remain explicit gates.

The explicit Unix-only test gate is `cargo test --all-features --locked --lib native_default_checksums_flex_and_uninitialized_geometry -- --ignored --nocapture`, with a fresh absolute `PARTMGR_EXT_METADATA_EVIDENCE` destination. Missing tools/destination or an existing destination fail. Its independent native fixtures use default mke2fs, retained input files, debugfs-authored inline/external xattrs, and e2fsck directory indexing; read-only e2fsck checks precede/follow inspection and the image bytes must remain identical. It covers a 131089-byte payload in bounded chunks plus independent debugfs dump comparison, exact non-UTF8 names, hardlink identity, indexed directory leaves, hidden ownership, and reservation refunds.
