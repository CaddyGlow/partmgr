# Filesystem specification and evidence ledger

Inventory date: 2026-10-07. This is milestone 0 planning evidence, not evidence
that a codec, native interoperability, crash recovery, or firmware gate passed.
Mutable online references must be pinned by revision/hash in each fixture manifest
before accepting an implementation profile. DCF is excluded.

Commands above are candidate oracle protocols, not recorded runs. Before execution,
confirm the installed tool's no-repair option. Record executable version, full
command, fixture generator, specification revision/hash, geometry/features, raw
image SHA-256, expected native names/metadata/content, stdout/stderr and exit code.
Repair tools run on disposable copies; compare before/after bytes and never count
silent repair as validation. Linux/kernel source references are implementation
references, not substitutes for missing normative specifications.

## Milestone 0 closure requirements

The inventory identifies all families and candidate profiles/oracles. Closure
still requires pinned normative documents where marked missing, versioned common
contracts and examples, finalized R1–R4 APIs, feature-specific capability rules,
independent fixture manifests, and actual evidence attached to each profile.
Later gates include malformed-input/fuzz bounds, ownership audits, interrupted
commit/recovery, preservation, numeric performance thresholds and regression
measurements. Host unit tests cannot close Windows capture/servicing, native
filesystem interoperability, physical-flash, or QEMU/OVMF boot gates.
