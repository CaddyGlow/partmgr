# Classic HFS immutable read profile

`fs_hfs::HfsVolume` reads bare classic HFS MDBs, allocation bitmaps, catalog and extents-overflow B-trees. Native object IDs retain their big-endian CNID and source domain 14. Names remain exact `NativeName::Bytes`; the reader never decodes a script encoding into guessed Unicode. `open_fork` exposes separate indexed data and resource forks, including empty forks, without reading their payload during inventory. `fs_hfs_tree::HfsTreeSource` implements the common tree contract after a complete clean supported-profile audit.

This is an initial strict profile, not full classic HFS family acceptance. The current native comparator accepts ASCII alphanumeric names, case insensitively, and empty thread keys. Punctuation, spaces and extended native bytes fail `Unsupported`; their full native collation and script semantics remain required expansion. HFS+, HFSX, embedded HFS+ wrappers, partition-map discovery, MFS, extents-tree self-overflow bootstrap, unknown catalog/volume flags and open file states are explicitly unsupported. These limits do not change the full family destination in `FILESYSTEM_PLAN.md`. HFS+ remains a separate engine.

The caller selects the exact bounded volume and guarantees immutable backing bytes through every retained handle. Source length and the retained primary MDB are checked before and after deferred reads. Those checks do not create a snapshot or detect every same-length payload mutation. EOF reads still check cancellation and source identity. Handles retain their source, metadata indexes and memory leases after the caller drops the volume.

The MDB establishes 512-byte logical sectors, a multiple-of-512 allocation-block size, at most 65,535 allocation blocks, and separate bitmap and allocation-arena locations. The boot blocks, primary MDB, bitmap, arena boundary gaps and last two sectors are never offered as free allocation ranges. The successfully-unmounted flag must be set and the inconsistent flag clear; unknown attribute bits fail. Classic HFS has no journal in this accepted profile. An `HFS` signature alone does not establish clean state. The caller supplies selected-volume length because the MDB does not independently encode the complete region length.

B-tree validation checks fixed 512-byte nodes, native record offsets, bounded header/map-node chains, node allocation bits, child bounds/heights/cycles, key order, fixed-size catalog index keys, child lower bounds, sibling links, leaf counts and unreachable allocated nodes. Catalog records retain native Finder/type/creator metadata and directory/file threads. File threads may be absent when their native flag says so; directory threads are required. Three inline extents and bounded indexed overflow records cover data and resource forks. Signed logical/physical EOF bounds, extent sums, physical arena bounds and orphan overflow records are checked. Physical allocations beyond EOF remain in the inventory and audit. CNID 5 bad-block records have explicit ownership and must agree with the spared-block flag.

Metadata retains native creation/modification ticks as seconds from 1904-01-01, with classic Mac local-time semantics and unavailable timezone. Access time, POSIX owner and mode have no corresponding established fields and remain absent. External sharing/security metadata remains explicitly uninspectable. Complete raw catalog records, backup dates, Finder flags and native byte-name keys are opaque metadata; physical fork locations and parent IDs require a relocation policy. There is no claim of faithful transplantation into another filesystem. Resource forks never disappear into ordinary data or host sidecars.

`fs_hfs_audit::audit_hfs` covers every allocation bit, complete physical system/user fork allocation, bad blocks, catalog parent/type/name/thread references, root name, namespace reachability, directory valence, volume/root file/directory counts and free-block summaries. It reports crosslinks, referenced-free blocks, lost allocations, topology defects and alternate MDB geometry/system-fork disagreements. Apple specifies that alternate MDB counts and dates may be stale; the audit does not compare those changing fields for byte equality. Free byte ranges are returned only for a complete defect-free accepted profile, only within the allocation arena. They grant no editing, repair or discard authority.

Explicit limits independently cap allocation blocks, total B-tree nodes, leaf records, extents and metadata work. Audit caps cover blocks, objects, depth, work and retained findings. Checked reservations precede proportional inventories, scratch, ownership maps and reports; pages, metadata and fork maps retain and refund leases. Cancellation, I/O causes, stale identities, malformed bounds and cap exhaustion propagate as errors. Unsupported or failed operations never provide a partial free-space proof.

Independent byte fixtures in `tests/fixtures/hfs_clean.rs` construct MDBs, bitmap bits, a catalog index and two leaves, native threads, a fourth overflow extent, separate forks and a nested child without production codecs. Tests exercise malformed offsets, cyclic children, geometry/dirty/wrapper/name profiles, allocation defects, stale alternate counts, source changes, cancellation, deferred failures, physical tails, bad-block ownership, work/depth/finding/memory caps and retained-handle refunds.

The enabled Linux native gate requires a fresh evidence directory and explicit hfsutils/TSK tool paths. It formats a 16 MiB image, uses hfsutils MacBinary copy for both forks and adds a nested child plus 80 sibling files, producing actual catalog index topology. Test-only independent raw insertion fragments the data fork and adds its overflow record while preserving the original native allocations/counts. hfsutils independently lists the catalog, reports free space and reads both forks back; framework inventory, payload and complete allocation proof agree. The unchanged image is checked by SHA-256 and byte equality around validators.

Stock hfsutils writes its CLI `.hcwd` state beneath the user's home. The retained 3.2.6 source tool uses a narrow `hcwd.c` override named `HFSUTILS_STATE_HOME` so disposable CLI state stays inside the evidence directory. All original archive C/header files are verified unchanged except that exact override; filesystem codecs and formatter algorithms are unchanged. Archive URL/hash, patch, compiler/build commands, logs and executable hashes are recorded in `/data/cache/partmgr-classic-hfs-tools/provenance.json`. No GPL codec code is included in the crate.

TSK 4.14 explicitly rejects classic HFS, reporting that only HFS+/HFSX and their wrappers are supported. Its required attempted command/version/error are retained as an unsupported oracle layer. This evidence establishes hfsutils/framework agreement; it does not establish TSK classic-HFS, macOS fsck/mount, or firmware acceptance. Missing enabled-gate tools or formatter provenance fail; ordinary host tests do not silently stand in for the native gate.
