# Owned offline NOR JFFS2 append and GC

`fs_jffs2_edit` implements the bounded profile `jffs2-owned-logical-nor-one-node-append-gc-v1`. This is an exclusively owned, offline logical NOR image protocol. It uses caller-declared little/big endian, complete power-of-two erase blocks, erased `0xff`, and one-to-zero programming aligned to 1/2/4 bytes. Mutable flash never implements immutable `ReadAt`. The immutable reader and new-image builder remain separate.

`Jffs2Editor::open` owns a `FlashStorage`, performs the shared complete checked scan and namespace audit, and reserves source domain 13 for session identities. `identity` includes the maximum inode/directory-entry version, including deletion histories. `replace` and `collect` produce exact bounded plans; `commit` uses a separately owned, freshly created, zero-header, pre-sized regular `Storage` journal. `into_flash` releases ownership so a caller can restart/reopen storage and call `recover` with the same independently verified 32-byte binding. Journal and target must be distinct exclusive storage objects; this identity is a caller obligation, not inferred from trait objects.

## Implemented operations and transformations

Replacement selects one existing, single-named regular file and writes one complete NONE inode, with at most the caller's `file_bytes` limit (never above 32768) and complete-node erase-boundary fit. The publication dirent selects a fresh inode number. Source mode, native 16-bit UID/GID, supported flags and access time survive; modification/change seconds are explicitly supplied. Raw headers/version counters and compression hints change. Hardlinked replacement, opaque extensions and larger/multiple-node replacement payloads fail before target mutation. Separate explicit namespace operations create regular files/directories/symlinks, add hardlinks, rename/move names and publish deletion tombstones; see [namespace contracts](filesystem-jffs2-namespace.md). Exact byte names are retained; there is no UTF-8 normalization or implicit symlink following.

GC selects one aligned erase block. It relocates every reachable inode with any accurate native inode header in the victim (conservatively including old versions), plus each latest live/deletion dirent in the victim. This includes tombstones: erasing a latest deletion without relocation could resurrect a lower-version name outside the victim. Relocated regular files use bounded multi-node NONE/ZERO groups with exact logical coverage and a final metadata record; see [multi-node GC contracts](filesystem-jffs2-gc.md). Live symlink inodes relocate as complete NONE nodes with exact 1..254 non-NUL target bytes. Every historical symlink version must independently satisfy that same complete-node profile; fragmented or compressed histories fail explicitly. Directory metadata and interpreted timestamps survive; native inode numbers, hardlinks, names, symlink target bytes and logical regular-file bytes remain equal. Raw headers, versions and allocation shape transform explicitly. Historical-only victims can be erased with no appended records. Already pristine victims are rejected.

The editor retains an inode-number floor across GC, so removing a high-number historical inode cannot reuse that number within the same session. Another session receives a different scope. Version/inode overflow fails preflight.

This completes these constrained append/erase/GC/recovery operations, not the full JFFS2 family roadmap. Inode-preserving multi-node range replacement/extend/truncate is available through the separate [file-edit contracts](filesystem-jffs2-file-edit.md). The original fresh-inode replacement retains its complete-node payload cap; GC now supports bounded fragmented regular files. Transactions beyond retained-intent limits, fresh-inode repointing of multiple hardlinks, destination-replacing rename, generalized live-space packing, kernel mount/recovery integration, and hardware/NAND/OOB/ECC remain outside this profile. Namespace create/link/rename/unlink and live symlink GC are additive offline transactions; they do not imply mount-visible atomic rename.

## Bounds and preflight

`Jffs2EditLimits` separately bounds complete reader scans, audit traversal, journal bytes, appended slots, complete file bytes and hash/readback scratch. Inventory, raw node locations, retained latest tombstones, planned node/preimage bytes, serialization, recovery parsing and temporary maps are charged to shared budgets with fallible allocation. Payload buffering is limited to one caller-bounded node; complete images are streamed for SHA256 and compared through a bounded positional overlay.

All slots are sorted/disjoint, four-byte aligned, contained within one declared erase block, and located only in completely erased or canonical-cleanmarker-only blocks. The first twelve bytes of every destination block are reserved. Existing live/history bytes are never overwritten by append. GC slots cannot overlap the victim. Space, ranges, native identities, hardlink policy, complete-image hashes, expected strict decode/audit and operation semantics are checked before journal preparation or target writes. Name and pristine-block lookup use bounded sorted indexes; duplicate proposed GC inode/name keys are checked by sorting.

Deferred mutable inspection uses a private borrowed `DecodeRead` capability and the shared checked scanner/audit. It cannot escape as a `ReadAt` or deferred immutable payload handle. Backing length and cancellation are rechecked. The original editor and plan cancellation contexts are retained and checked at mutation boundaries. An I/O error retains its cause; it does not become an empty stream or a clean scan.

## Journal and publication order

The private journal format has two 512-byte state headers followed by the exact bounded body at offset 1024. Headers contain magic/version, sequence/state/operation, geometry/endian/length, caller binding, body SHA256, baseline/copied/final image SHA256, inode floor, slot count and optional victim/preimage bounds. Reserved bytes must be zero. The body contains checked offset/length descriptors and exact new node bytes, plus a bounded GC victim preimage. Each header has SHA256 over its first 480 bytes. The highest valid header wins; conflicting static transactions, impossible state/sequence combinations and malformed later records fail before any target or journal recovery writes.

The body is written, flushed and compared. PREPARED is then written, flushed and compared before the first target program. Subsequent state headers alternate sectors, preserving the preceding valid state across a torn header update. Header/body readback also detects a backend returning successful counts for corrupted journal bytes. This format supplies integrity and exact intent bounds, not cryptographic authorization; caller binding and exclusive access are still required.

Each new native node is programmed body/data first, then its twelve-byte header. Complete node readback follows. For replacement, staged inode bytes are read back and flushed before the final higher-version dirent header is programmed. Old live bytes remain intact during partial append, but the ordinary strict reader can reject torn nodes. Exact bound-intent recovery is required before ordinary reopening; there is no promise that the old namespace remains readable through the strict reader before recovery.

After publication, actual complete target SHA256 and shared strict scan/audit must match the plan. COMPLETE is flushed and compared only afterward. Reports distinguish accepted/read-back bytes and sticky mutation uncertainty. A failure may hide partial mutation even when accepted bytes are zero.

## Recovery and erase authorization

PREPARED recovery masks only recorded append slots to their proven old erased bytes. The entire baseline SHA256 and complete namespace audit must match. It rejects every victim change; victim masking and erase completion are forbidden at this state. All observed append bytes must obey `(observed & expected) == expected`, the exact condition for legal one-to-zero replay. Recovery writes the same exact bytes, never blindly restores cleared NOR bits.

GC checks both the expected copied image and expected post-erase image before mutation. All reachable names/native inode numbers, interpreted supported metadata and logical payload SHA256 values must remain equal. The copied inventory must have no reachable latest inode header, mapped data, latest live dirent or latest deletion dirent in the victim. Comparing the expected erased namespace/payload also covers ZERO fragments and truncation dependencies that do not have a data physical offset.

All replacement nodes are programmed, read back and flushed before COPIED is written, flushed and compared. Only durable COPIED permits victim masking using the saved preimage and finishing a partial erase. Observed victim bits must satisfy `(observed & preimage) == preimage`, so they can only reflect unchanged bytes or partial erase transitions. Recovery reestablishes/readbacks/flushes exact replacements and repeats the ownership/namespace proof before completing erase. The saved preimage serves baseline validation only and is never restored to NOR.

After erase, actual full-image hash and ordinary strict scan/audit must pass before COMPLETE. Completed recovery checks the actual final digest and namespace without writes. Recovery can itself be interrupted and restarted. Flash uncertainty is sticky: a later successful logical recovery report retains an existing backend uncertainty flag. The editor also stops after any commit failure; its failure report conservatively marks uncertainty after target attempts even if the backend has no physical-error flag. Releasing flash does not waive that report or caller obligation: reopen owned storage before planning another edit. No rollback or physical power-loss guarantee is claimed.

## Evidence

Portable tests construct independent native headers/CRCs and a six-block image with regular files, hardlinks, a symlink outside the victim, a latest deletion in the victim and an older live name outside. They verify append, shrink semantics, live GC, historical-only GC/inode floor, both endian encoders, non-UTF-8 names, exact unchanged framing and lease refund. Checksum-recomputed negative journals cover wrong state/sequence, overlapping slots/victim, regressed inode floor, wrong node type/payload sizing, a malformed later node and unauthorized new names; target and journal writes stay zero. Binding, incompatible program/erase bits, changed outside bytes, COMPLETE digest mismatch, caps/cancellation and causal failures are exercised.

The fault model records a distinct durable byte buffer on every successful flush. Every target program/erase write, journal write and flush boundary is cut with hidden partial writes or failed flushes. Restart independently retains or discards volatile target and journal bytes (four combinations). The same matrix interrupts recovery itself and restarts again, then repeats COMPLETE recovery without writes. These are declared model invariants, not hardware power-loss evidence.

The explicitly enabled native gate requires `JFFS2_EDIT_EVIDENCE` and `JFFS2_TOOLS` containing `mkfs.jffs2`, `jffs2dump` and `jffs2reader`; missing enabled prerequisites fail. It independently produces a mtd-utils 2.3.1 base and disjoint incremental history, frames it at offset 8192, and uses actual `FileStorage` flushes. It validates a 5013-byte append, modeled partial-program/restarted 333-byte shrink, and modeled partial erase/restarted GC after COPIED. Prefix/suffix, the disjoint incremental block and original source remain unchanged.

`jffs2dump` independently validates native nodes/CRCs after each completed state. The final gate additionally extracts the actually relocated five-byte `a_dummy` inode, separately from the selected `/payload` inode outside that GC victim. The legacy bundled `jffs2reader` validates only completed, CRC-validated single-node `/payload` bytes; it has no CRC validation, does not reconstruct generalized fragments reliably and mishandles some version-zero dirents. Jefferson's inode-keyed reconstruction does not certify replacement histories. These tools do not certify torn namespace selection, mount recovery or physical media.

The receipt records exact argv, versions, tool/input/output/test binary hashes and baked source hashes, with live source equality at start and source/tool/test executable equality at end. Primary sources may be retained through `JFFS2_SPEC_ARCHIVE`. The native profile is little endian; big endian authoring/GC is presently portable independent-fixture evidence.
